# Kateryna-Truba

Робочий репозиторій для блогу.

## Запам'ятовувати нічого не треба

Просто напиши агенту звичайними словами, чого хочеш — або взагалі нічого не пиши, а кинь
текст чи посилання. Він сам розбереться, що з цим робити. Назви інструментів знати не
потрібно.

| Що ти робиш | Що станеться |
|---|---|
| Кидаєш свій текст | Відредагує: русизми, канцелярит, AI-мова. Покаже, що змінив і чому |
| Кидаєш посилання на статтю | Витягне текст і зробить конспект |
| Кидаєш посилання на YouTube | Витягне транскрипт і зробить конспект |
| «Хочу написати про Х» | Запропонує структуру посту |
| «Хочу написати про Х, ось джерела» | Напише чернетку |
| «Розкидай це по соцмережах» | Зробить версії для Instagram, Threads, LinkedIn, розсилки |

Це працює тому, що в репозиторії є
[`.cursor/rules/skills-routing.mdc`](.cursor/rules/skills-routing.mdc) — файл, який завжди
в контексті агента й забороняє йому питати тебе про вибір інструментів. Якщо агент раптом
почне питати «який скіл застосувати?» — це збій, скажи мені.

Далі в цьому файлі — технічні деталі. Читати не обов'язково.

## Що вже встановлено

Скіли лежать у `.cursor/skills/`. Оскільки вони закоммічені в репозиторій, вони працюють
і в локальному Cursor, і в Cloud Agents (глобальні скіли з `~/.cursor/skills/` у Cloud
Agents **не** потрапляють — тому саме проєктна тека).

### Збір матеріалу

| Скіл | Що робить |
|---|---|
| `article-extractor` | Витягує повний текст і метадані статті з URL — щоб не копіювати вручну. |
| `youtube-transcript` | Дістає транскрипт з відео на YouTube і готує з нього конспект. |

### Написання

| Скіл | Що робить |
|---|---|
| `blog-draft` | **Українською.** Повний процес: дослідження → мозковий штурм → план → ітеративна чернетка з версіями у теці `blog-posts/YYYY-MM-DD-тема/`. |
| `blog-outline` | Швидкий структурний план посту з урахуванням того, що вже ранжується в пошуку. |

### Редактура

| Скіл | Що робить |
|---|---|
| `ukrainianizer` | **Найкорисніший для українського тексту.** Прибирає русизми, канцелярит, плеоназми, англіцизми, AI-лексику й приховані Unicode-вотермарки. Має шість словників у `references/`. |
| `avoid-ai-writing` | Те саме, але для англійського тексту й значно детальніше: 21 категорія «AI-ізмів», таблиця замін, режими `detect` / `rewrite` / `edit`, профілі голосу (`casual`, `professional`, `blunt` тощо). |
| `i-have-adhd` | Той самий ADHD-скіл, про який ти питала. Це **фільтр формату виводу**, не редактор тексту: змушує агента ставити відповідь і наступний крок на перший рядок, нумерувати кроки, не хоронити висновок у преамбулі. Корисний і як стиль спілкування з агентом, і як чек-ліст «чи можна це прочитати за 10 секунд» для власних постів. |

### Дистрибуція

| Скіл | Що робить |
|---|---|
| `blog-repurpose` | З одного посту робить тред у X, пост і статтю для LinkedIn, Threads, Bluesky, скрипт для YouTube/Shorts/TikTok, лист для розсилки, пост для Reddit — з підбором тону під кожну платформу. |

Походження, автори, ліцензії та внесені правки — у [`.cursor/skills/ATTRIBUTION.md`](.cursor/skills/ATTRIBUTION.md).
Усе під MIT.

## Як це працює під капотом

Cursor показує агенту назви й описи (`description`) усіх скілів, і агент сам вирішує, який
узяти. Це рішення моделі, а не жорстке правило, тому поверх нього лежить
[`.cursor/rules/skills-routing.mdc`](.cursor/rules/skills-routing.mdc) з `alwaysApply: true` —
він завжди в контексті й робить три речі:

1. Забороняє агенту питати Катерину про вибір скіла або просити слеш-команду.
2. Розводить `ukrainianizer` (український текст) і `avoid-ai-writing` (англійський), бо
   описи в них схожі, а документованого правила пріоритету для скілів, що перетинаються,
   у Cursor немає.
3. Вимагає проганяти будь-який український текст через `ukrainianizer` перед показом
   результату.

Правило — це проза в контексті, а не механізм із гарантією. Якщо агент раз за разом бере
не той скіл, надійніше уточнити `description` у самому `SKILL.md`.

`i-have-adhd` тут застосовується автоматично до кожної відповіді: в оригіналі він мав
`disable-model-invocation: true` і вимагав ручного виклику `/i-have-adhd`, але цей рядок
прибрано. Вимикається фразою «stop adhd mode».

Викликати скіли вручну теж можна, просто це не обов'язково: набрати `/` у чаті й вибрати
скіл зі списку (приєднається до одного повідомлення), або **Option+Enter** / **Alt+Enter**,
щоб скіл тримався всю сесію.

### Чого скіли не бачать

Правила й скіли працюють лише в Agent (Chat). На Tab-автодоповнення, Inline Edit і
Bugbot вони не впливають.

## Що ще є на GitHub

Це те, що я передивилася, але не додала в репозиторій — або завелике, або вузькоспеціальне.
Ставити варто вибірково, під конкретну потребу. Зірки станом на серпень 2026.

### Великі набори для блогу

Працює з Next.js MDX, Astro, Hugo, Jekyll, WordPress, Ghost, 11ty, Gatsby. Ставиться цілком одним скриптом — сенс є, якщо блог уже великий і потрібна аналітика по наявних постах.
- **[coreyhaines31/marketingskills](https://github.com/coreyhaines31/marketingskills)** (49 скілів) — маркетинг ширше за блог: копірайтинг, SEO, CRO, розсилки, ціноутворення, аналітика.

- **[jonathimer/devmarketing-skills](https://github.com/jonathimer/devmarketing-skills)** (33 скіли) — якщо контент технічний: стратегія для Hacker News, технічні туторіали, документація як маркетинг, Reddit, розсилки.
- **[sergebulaev/linkedin-skills](https://github.com/sergebulaev/linkedin-skills)** (~618 ★) — окремо під LinkedIn: пости, комментарі, аудит і оптимізація профілю, контент-план.

## Написати власний скіл

Мінімум — тека з файлом `SKILL.md` у `.cursor/skills/назва-скіла/`. Обов'язкові поля
frontmatter лише два: `name` (малі літери, цифри, дефіси; має збігатися з назвою теки) і
`description` (за ним агент вирішує, чи брати скіл). Довідкові матеріали виносяться в
сусідні файли й підтягуються за потреби.

Найкращий шаблон для наслідування з того, що тут є — `ukrainianizer`: короткий `SKILL.md`
з процесом і шість словників у `references/`, які завантажуються тільки коли потрібні.
